## 2. 作業の型（毎回これ）

1. `git fetch origin main` → `git checkout -b <branch> origin/main`（作業ツリーの未コミット変更はそのまま持ち越せる）
2. 実装 → `npx tsc --noEmit -p .` → `npm test` → `npx next build`（**3つとも通す**）
3. commit（末尾に `Co-Authored-By: Claude ... <noreply@anthropic.com>`）→ push → `gh pr create` → `gh pr merge --merge --delete-branch=false`
4. 本番デプロイ確認: `gh api repos/itarutakasaka-glitch/rental-crm/commits/<merge sha>/status` の `Vercel` が `success`（50〜90秒）
5. 本番ヘルス: `curl https://tama-fudosan-crm-2026.vercel.app/api/cron/timeout-check -H "Authorization: Bearer $CRON_SECRET"` と `/api/cron/agent` が 200・`errorCount:0`（`CRON_SECRET` は `crm-project-new/.env.local`）
6. 「反映済み」と言うのは 4・5 を確認した後だけ（CLAUDE.md の本番反映ルール）

## 3. この環境の落とし穴（全部このセッションで実際に踏んだ）

| 現象 | 対処 |
|---|---|
| **Prisma CLI（`migrate diff` / `db push` / `db execute` / `migrate deploy`）がローカルから DB に届かずハングする** | マイグレーション SQL は**手書き**して `prisma/migrations/<timestamp>_<name>/migration.sql` に置く（既存ファイルの書式に合わせる）。適用は Vercel のビルド（`prisma migrate deploy && prisma generate && next build`）に任せる。DB を触る一回限りの処理は `verifySharedSecret` 付きの管理 API を作って本番で叩く |
| `npx prisma generate` は動く（1〜3分） | スキーマを変えたら必ず実行してから tsc |
| **Vercel Preview は必ず落ちる**（`P1013 scheme not recognized`。Neon 連携の Preview 用接続文字列の問題） | Preview では検証しない。マージ→本番で検証、失敗したら revert |
| `next build` がこの PC では 3〜10 分。Bash ツールのタイムアウト（最大10分）で殺されることがある | `nohup ... > log 2>&1 &` で切り離してログを後で読む。`ScheduleWakeup` で 5〜7 分後に確認 |
| **削除したルートがあると `.next/types` の古いスタブで tsc が失敗する** | `rm -rf .next/types` してから tsc |
| Git Bash と Windows Node で `/tmp` の解釈が違う | 一時ファイルは scratchpad の絶対パスを使う |
| ローカル git が固まった時に強制終了すると `index.lock` が残り、ワークツリーの index が壊れる | `git worktree unlock` → `remove -f -f`。どうしても動かない時は GitHub API（`gh api repos/.../contents/<path>` PUT）でコミットできる |
| 本番 DB を直接見る手段が無い | 監査ログや状態列の実データ確認は、読み取り専用の管理 API を作るか Neon ダッシュボードで。**「書けているはず」で完了と言わない** |
| `heyacules-ai` 本体リポは巨大でワークツリーが 60 本以上 | ポータル（`manual-vercel`）の共有ファイル `app/page.jsx` を触る時は必ず `origin/main` から新しいワークツリーを切る（CLAUDE.md） |

## 4. 実装の約束事（仕様書の要点・破ると事故る）

- 顧客IDを受け取る API は **`requireCustomerAccess`** 以外で所属を判定しない。会社設定の変更は `requireAdminUser`。
- 組織IDは**ログインユーザーか顧客レコードから導出**する。文字列リテラル `"org_default"` はテスト（`src/lib/no-org-default.test.ts`）で落ちる。
- エージェントの状態は **`Customer.agentState`** のみ。遷移は `src/lib/agent-state.ts` に足す。memo に状態を書かない。
- 共有秘密鍵の検証は **`verifySharedSecret`**（`src/lib/shared-secret.ts`）。独自比較を書かない。cron はヘッダのみ、外部 webhook だけ `allowQuery: true`。
- 送信の宛先は**顧客レコードから**。リクエスト本文の宛先は使わない。
- 個人情報を扱う操作は **`logAudit` / `logFieldChanges`**（`src/lib/audit.ts`）で記録。失敗しても本処理は止めない。
- 自動送信は `autoReplyEnabled && autoReplyMode === "AUTO_SEND"` の会社のみ。既定は下書き（`Message.status=PENDING`）。
- 画面のカードは縦1列（横並びグリッド禁止）。白基調＋ゴールド `#d4a017`。
- 会話・報告は日本語。時刻は JST 表記。
